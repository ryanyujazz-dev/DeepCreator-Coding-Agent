# 全量评测批次需求

## 范围

在开发者评测中心增加可持久化的全量评测批次。用户可以一次启动数据集全部 Case，逐项查看真实执行过程，并在侧边栏查看批次加权结果。普通单次评测行为保持不变。

## 用户故事与验收条件

1. 作为评测用户，我希望从“评测集”标题直接启动全部 Case。
   - 当用户点击全量评测按钮时，系统应为每个 ready Case 创建独立 Eval Run，并最多同时执行 4 个。
   - 当存在任何活动中的单次或全量评测时，系统应拒绝启动新的评测批次。
2. 作为评测用户，我希望观察批次内任一 Case 的执行过程。
   - 当用户点击评测集中的 Case 或批次结果中的子项时，系统应展示对应 Run 的实时对话、工具活动和评分阶段。
3. 作为评测用户，我希望看到可信的全量分数。
   - 当批次全部 Case 终止时，系统应按 easy=1、medium=1.5、hard=2 计算加权平均分。
   - 当 Case 失败、取消或没有评分结果时，系统应将该 Case 作为 0 分计入完整分母。
4. 作为评测用户，我希望刷新后仍能查看批次结果。
   - 当 Runtime 重启时，系统应从持久化文件恢复批次与子 Run；中断的子 Run 应明确失败，批次应重新结算。
5. 作为评测用户，我希望区分全量和单次历史。
   - 侧边栏应分别展示“全量评测结果”和“单次评测结果”，批次子 Run 不应重复出现在单次结果中。
6. 作为评测用户，我希望可以暂停一个长时间运行的全量批次。
   - 当用户暂停全量评测时，系统应停止派发新的 queued Case，并允许已经开始的 Case 安全结束。
   - 当用户继续已暂停的批次时，系统应重新填充最多 4 个并发槽，并从原队列继续执行。
   - 当页面刷新或 Runtime 重启时，系统应保留批次暂停状态。
7. 作为评测用户，我希望所有评测默认使用统一的 LLM Judge。
   - 当用户没有显式修改评分配置时，单次评测、全量评测和评测 CLI 应默认使用 provider Judge 与 `deepseek-v4-flash`。

## 非目标

- 本次不增加跨模型对比、自定义 Case 子集或暂停正在执行的模型请求。
- 本次不改变单个 Case 的 100 分评分维度。
