# 设计资源规范及布局规范

状态：生效中。本文约束 renderer 的视觉资源、排版、间距、布局与交互表面；执行流的状态语义仍以 [对话展示模型](conversation-display-model.md) 为准。

## 设计原则

- 使用少量稳定令牌表达层级，不用随机字号、颜色或间距制造差异。
- 同一语义必须同形、同尺寸、同状态反馈。状态优先通过颜色、图标和文案表达，不随意缩小文字。
- 同一行的图标与文字必须横向排列并垂直居中对齐。使用同一个 `flex`/`grid` 对齐上下文和 `align-items: center`，禁止用单独的 `margin-top`、`top` 或 `transform` 人工补齐。
- 布局由父容器的 `gap` 和 `padding` 控制；子组件不得用不可解释的外边距修补位置。
- 新样式出现两次即评估抽取；涉及确认、焦点、禁用或危险操作时，即使只出现一次也优先使用公共组件。

## 字体与资源

界面正文统一使用 `HarmonyOS Sans SC`，回退到 `Microsoft YaHei UI`、`PingFang SC` 和 `sans-serif`。代码、终端输出、路径对齐场景使用 `--font-family-code`。不得在业务组件声明独立字体栈。

项目当前使用资源包中的 `HarmonyOS_Sans_SC.ttf`，其内部家族名为 `HarmonyOS Sans SC` / `鸿蒙黑体`，是字重轴 `40–900` 的可变字体。不要与仅拉丁字符的 `HarmonyOS_Sans.ttf`、窄体 `HarmonyOS_Sans_Condensed.ttf` 或繁体 `HarmonyOS_Sans_TC.ttf` 混用。

字体文件必须保持原样，不得裁剪、转换或改名后单独分发。项目必须保留 `THIRD_PARTY_NOTICES.md` 和完整授权文件。图标优先使用 `lucide-react`；自定义 SVG/Lottie 仅用于品牌或具有明确状态变化的动效，并提供静态降级。

| 角色 | 字号 / 行高 | 字重 | 用途 |
| --- | --- | --- | --- |
| 展示标题 | 28 / 38px | 650 | 空态主标题 |
| 页面标题 | 20 / 28px | 650 | 弹窗、独立页面 |
| 区块标题 | 16 / 24px | 600 | 面板分组 |
| 通用正文 | 14 / 24px | 400 | 说明、长文本 |
| 对话正文 | 13 / 21px | 500 | `content`、思考和工具主文字 |
| 控件文字 | 13 / 20px | 500 | 导航、按钮、菜单 |
| 辅助文字 | 12 / 18px | 400 | 时间、目标、计数 |
| 微型标签 | 11 / 16px | 500 | 极短状态，不承载正文 |
| 代码文字 | 12 / 18px | 400 | diff、命令输出、代码块 |

同一级只使用一个字号。强调使用 `600`，标题最高使用 `700`；不要用过粗字重替代清晰层级。

## 色彩与状态

主题色沿用 `--theme-blue`，悬浮或强调使用 `--theme-blue-dark`，选中背景使用 `--theme-blue-light`，不可用状态使用 `--theme-blue-muted`。正文、辅助文字、边框和表面色应通过语义令牌引用，禁止在新组件中复制近似蓝色。

交互状态顺序固定为：默认、`hover`、`focus-visible`、按下、选中、禁用、危险。键盘焦点必须可见，不能只依赖颜色；危险操作使用红色语义并进入公共确认弹窗。

## 间距与圆角

基础间距单位为 `4px`。允许值为 `2、4、6、8、12、16、20、24、32、40、48px`；`10、14、18px` 仅用于已有组件的光学校准。常用规则如下：

- 图标与文字：`6px`；同组控件：`8px`；列表行：`4px`。
- 紧凑控件内边距：横向 `10px`；常规卡片：`16px`；主面板：`24px`。
- 对话段落垂直间距由容器统一管理；工具条目与 content 不额外制造独立大间隔。
- 小卡片圆角 `8px`，行项目 `10px`，浮层 `16px`，输入框 `22px`，胶囊使用 `999px`，圆形按钮使用 `50%`。

外边距只负责组件与外部区域的关系。组件内部一律使用 `padding` 或 `gap`，列表首尾不得各自叠加间距。

## 令牌与实现位置

所有全局设计令牌只在 `src/styles.css` 顶部的唯一 `:root` 中声明。字体使用 `--font-family-*`，排版使用 `--type-*`，间距使用 `--space-*`，圆角使用 `--radius-*`，颜色和状态使用 `--color-*`、`--theme-*`，布局使用 `--layout-*`。业务组件只能消费语义令牌，不得新建第二个根变量块或复制近似色值。

执行流的共享列由 `--execution-icon-column` 和 `--execution-column-gap` 控制，相邻槽位的纵向距离统一由 `--execution-slot-gap` 控制。调整它们时必须同时检查聚合头、成员行、详情标题和进行态，禁止在子选择器中用补偿值覆盖。

## 三类交互表面

| 形态 | 尺寸 | 视觉 | 适用场景 |
| --- | --- | --- | --- |
| 长行圆角矩形 | 高 `36px`，横向 `12px`，圆角 `10px` | hover 中性灰，selected 淡主题蓝 | 项目、任务、菜单长行 |
| 胶囊按钮 | 最小高 `28px`，横向 `10px`，圆角 `999px` | 紧贴内容，不拉伸 | 完全访问、模型选择、短筛选 |
| 圆形图标按钮 | `28 x 28px`，圆角 `50%`，图标 `14-16px` | 无文字，必须有 `aria-label`/tooltip | 发送、关闭、更多、设置 |

三类表面只能改变尺寸和轮廓，hover、focus、disabled 的色彩与动效必须共用同一状态令牌。不要把圆角矩形按钮写成宽度变化的胶囊，也不要用圆形按钮承载两个图标或长状态。

## 主布局

- 顶部应用栏高 `42px`，只承载窗口级导航和视图动作。
- 左侧栏默认宽 `272px`，可调范围 `220-360px`；侧栏项目两侧必须保留行级间距。
- 侧栏的置顶任务和置顶项目统一进入顶部“置顶”区，并从普通“项目”区移除以避免重复；没有任何置顶项时不得渲染该区标题或占位间距。
- 侧栏采用紧凑列表节奏：分区标题到首行使用小间距，项目标题与所属任务紧邻，相邻项目组只保留可辨识的单级间距；不得叠加行尾 `padding` 和组级 `margin` 扩大空白。
- 对话列最大宽 `860px`，大屏水平留白 `38px`，中屏 `24px`，紧凑屏 `16px`。
- Composer 最大宽 `884px`，与对话列共用中心轴；不得用固定 `left` 位移制造视觉对齐。
- 右侧工作区最小宽 `360px`、最大宽 `960px`。打开后优先压缩留白，不能让对话正文低于可读宽度。
- 小于 `760px` 时进入紧凑布局：隐藏常驻侧栏，主内容占满，浮层不得越出 `8px` 安全边距。

## 对话与工具执行流

`content`、思考主文案、工具活动主文案、聚合头、成员行和详情标题统一使用 `--type-conversation-size` 与 `--type-conversation-line-height`。它们的视觉层级只能通过灰度、图标、展开箭头、状态文案和纵向关系表达，不能通过缩小字号或增加横向缩进表达。

正文槽位与工具执行流使用两套明确的水平基线：正文保持自然左边界；工具执行流固定使用一套共享的“图标列 + 文字列”。工具执行流的三层结构必须如下：

```text
[图标列] [聚合头文字列] [展开箭头]
[图标列] [成员行文字列] [展开箭头]
[图标列] [详情标题文字列]
```

- 聚合头、成员行和详情层的图标必须处于同一条垂直线上，文字也必须处于同一条垂直线上。
- 展开子层级只增加纵向内容，不能新增 `padding-left`、`margin-left`、嵌套列表缩进或水平 `transform`。
- 图标列使用统一固定宽度，图标和文字横向排列并通过 `align-items: center` 垂直居中。
- 正文没有图标时不需要预留空白图标列；正文左边界与工具文字列不要求重合。
- 详情中的原始代码、diff 或终端输出可以使用等宽字体，内容面板可横跨完整工具行，但面板外边界不能相对成员行继续向右缩进。
- content、reasoning、工具进行态、聚合头和成员行切换时，字号、行高以及工具流内部两列的位置不能跳动。
- 主槽位、聚合头、活动槽位及相邻历史步骤之间必须使用同一个 `--execution-slot-gap`；槽位自身不得用 `padding-bottom` 或 `margin-bottom` 模拟槽位间距，展开详情只管理本槽位内部间距。
- 对话区工作流内的可交互内容统一使用文字、图标、下划线或展开箭头的颜色变化反馈 hover、展开与选中状态，禁止添加背景高亮块。`focus-visible` 仍必须保留清晰焦点环。
- 代码块、命令输出、diff 和终端正文可以保留中性底色作为内容分区；该底色是静态内容载体，不能随 hover、展开或选中而变化。

工具目标、耗时和二级说明可使用 `12px`；命令输出和 diff 使用代码字体。活动槽位、聚合时机、空槽位保持及 start/done 稳定性不得由视觉组件自行推断，必须消费 projection 结果。

## 公共组件策略

现有业务组件应优先复用：

- `OverflowFadeText`：所有可能溢出的单行标题；淡出只发生在文字容器内部。
- `PanelResizeHandle`：左右面板拖动、键盘调节和双击复位。
- `MarkdownContent`：模型正文、代码块、表格和 Mermaid。
- `ThinkingLoader`、`AnimatedFolderIcon`：具有明确语义的状态动效。
- `ConfirmationDialog`：普通与危险确认，统一标题、说明、Portal、焦点锁定和异步 busy 状态；`SidebarConfirmationDialog` 只保留业务适配。

公共视觉原语位于 `src/components/ui/ControlPrimitives.tsx`：

- `RowAction`：长行圆角矩形，统一 hover、selected、尾部操作区和溢出淡出。
- `PillButton`：短文字/图标按钮，统一高度、胶囊轮廓和菜单展开态。
- `IconButton`：圆形单图标按钮，统一尺寸、tooltip、焦点和禁用态。
- `FloatingSurface`：菜单、popover、hover card 的边框、阴影和表面色。
- `DisclosureRow`：聚合头、文件行和命令行的展开状态与键盘行为。

公共组件负责外观与交互契约，业务组件只提供语义、图标、文案和事件。不要通过父级选择器覆盖公共组件内部结构。

## 响应式与验收

每次 UI 变更至少检查 `1440px` 桌面、`1024px` 窄桌面和 `760px` 紧凑宽度。验收必须覆盖默认、hover、键盘焦点、选中、禁用、加载、失败、长中文、长英文路径以及 125% 系统缩放，并确认同一行内的图标与文字始终垂直居中。执行流还必须展开到第三层验收：三层字号与行高一致、图标列一致、文字列一致，折叠与展开过程中不出现水平位移。

提交前运行 `npm run build` 与相关测试。新增视觉模式时同步更新本文；改变执行流语义时更新 `conversation-display-model.md`，不能把两类规范混在组件注释里。
