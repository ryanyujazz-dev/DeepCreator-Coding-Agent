# ADR-008：模型完成信号与 Runtime 完成门

## 状态

已接受，2026-07-26。

## 背景

模型可能在一次响应中返回正文、工具调用或两者，也可能在托管命令仍运行、任务计划尚未收尾时提前生成看似最终的回答。Runtime 不能从正文措辞推断“模型是否真的完成”，否则会形成脆弱的文案识别规则；但 Runtime 仍必须保护自己拥有权威事实的生命周期约束。

## 决策

1. Provider 的结构化响应是模型步骤的协议事实。没有工具调用且 finish cause 为 complete 时，模型表达了结束当前步骤的意图。
2. Runtime 不检查“稍后继续”“接下来”等自然语言，也不根据回答内容强制模型继续工作。
3. Runtime 在接受最终回答前执行完成门，只检查本地可证明的事实：
   - 当前 Run 不存在仍在运行的托管命令；
   - 已启用的任务计划已经在独立工具步骤中完成维护，不存在 `pending` 或 `running`；
   - Provider 流和工具调用协议完整；
   - Run 没有进入等待、取消或失败状态。
4. 完成门拒绝一次候选回答时，该正文只作为内部轨迹保存，并向模型追加结构化、可操作的纠正消息。纠正完成后的下一轮才允许生成最终回答。
5. 由 Provider 内容长度、内容策略、资源不足或协议错误导致的终止不视为成功完成。

## 后果

Runtime 不会和模型争夺自然语言语义判断，但仍能保证命令、任务和协议生命周期闭合。新增完成约束必须来自 Runtime 可验证事实，并集中进入完成门；不得继续在主循环中增加分散的正文启发式判断。

## 不做

- 不根据中文或英文完成时态判断任务是否结束。
- 不因为模型提到“下一步”就自动重试。
- 不接受仍有未配对工具结果或运行中命令的最终正文。
