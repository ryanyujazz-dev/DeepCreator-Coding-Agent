# Application updates

DeepCreator uses Electron's native `autoUpdater` through `update-electron-app`. Packaged macOS and Windows builds check the public GitHub release feed at startup and every six hours. Development builds and unsupported platforms never contact the update service.

The Renderer receives only serializable update state. Feed configuration, native updater calls, downloads, Runtime shutdown and installation remain in Electron Main. The sidebar control can request a check and can call `quitAndInstall` only after Electron reports that the update has finished downloading.

## Release contract

1. Bump `package.json` to a new SemVer version.
2. Create the matching `v<version>` tag. The release workflow rejects a mismatched tag.
3. The macOS jobs publish separate Apple Silicon (`arm64`) and Intel (`x64`) Forge ZIP files used by Squirrel.Mac.
4. The Windows job publishes `DeepCreator-Setup.exe`, a portable ZIP, the full `.nupkg`, delta metadata and `RELEASES` generated by Squirrel.Windows. The release job must install the generated setup on its Windows runner before the artifacts are accepted.
5. The GitHub Release must be public, non-draft and non-prerelease before `update.electronjs.org` offers it to clients.
6. Never replace artifacts under an existing version. Publish a new patch version instead.
7. Every tagged Release includes `SHA256SUMS.txt`; publish it beside the installers so testers can verify downloads.

The default feed is `https://update.electronjs.org/ryanyujazz-dev/DeepCreator-Coding-Agent`. Forks can override `DEEPCREATOR_UPDATE_HOST` and `DEEPCREATOR_UPDATE_REPOSITORY` at build time.

## Signing

macOS automatic updates require a Developer ID signed application. Forge switches from its local ad-hoc development signature to hardened signing and notarization when all of these variables are present:

- `APPLE_SIGNING_IDENTITY`
- `APPLE_KEYCHAIN` when a non-default CI keychain is used
- `APPLE_ID`
- `APPLE_ID_PASSWORD` containing an app-specific password
- `APPLE_TEAM_ID`

The release workflow imports the Developer ID Application certificate when these GitHub Actions secrets are configured:

- `APPLE_CERTIFICATE_BASE64`
- `APPLE_CERTIFICATE_PASSWORD`
- `APPLE_SIGNING_IDENTITY`
- `APPLE_ID`
- `APPLE_ID_PASSWORD`
- `APPLE_TEAM_ID`

Windows Squirrel updates work without a certificate, but the installer should be Authenticode signed before broad public distribution to reduce SmartScreen warnings. The workflow signs Windows release artifacts when `WINDOWS_CERTIFICATE_BASE64` and `WINDOWS_CERTIFICATE_PASSWORD` secrets are present. Builds remain possible without either platform's signing secrets so internal smoke testing is not blocked.

For an unsigned friends-only preview, macOS users must allow the application once in **System Settings → Privacy & Security**, and Windows users may need **More info → Run anyway** in SmartScreen. macOS automatic updates are not considered reliable until the app has a stable Developer ID signature; publish a new installer and ask preview users to download it manually in the meantime. See [Friends preview release](friend-preview-release.md) for the complete operator and tester checklist.

## User-visible states

- `idle` / `current`: manual check is available.
- `checking`: the release feed is being queried.
- `downloading`: Electron is downloading in the background.
- `ready`: the update button is highlighted and offers **Restart and update**.
- `installing`: the local Runtime is stopped before Electron restarts.
- `error`: the current installation remains untouched and the user can retry.
